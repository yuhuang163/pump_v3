# 系统设计说明书

## 1. 目标与范围

本仓库是一个面向智能穿戴吸奶泵的嵌入式固件框架，目标是将产品逻辑、算法能力、硬件抽象和框架能力分层管理，保证同一套代码能在不同产品形态下通过 `overlay/` 进行定制。

系统整体上遵循以下设计原则：

- 功能按模块分层：业务逻辑与框架逻辑分离
- 代码可裁剪：通过 boards/configs 统一管理宏开关
- 业务定制隔离：`overlay/` 负责产品差异化，`trunk/` 保持通用
- 跨模块协作通过统一消息与广播机制，而不是直接耦合调用

## 2. 分层结构

```text
overlay/     产品定制层
trunk/       共用框架层
library/     算法和通用库
drivers/     硬件抽象层
boards/      板级配置与宏聚合层
```

其中：

- `overlay/` 承担产品逻辑、资源、UI、协议和测试挂钩
- `trunk/` 承担框架基础设施、模块注册、状态机、协议总入口和模块管理
- `drivers/` 是底层外设设备的抽象实现
- `boards/` 负责顶层宏定义和分区布局的统一入口

## 3. 关键模块

### 3.1 业务模块

业务模块一般位于 `overlay/` 和 `trunk/root_source/` 中，重点关注：

- 吸奶泵控制
- 蓝牙/协议处理
- OTA / 升级
- 资源管理
- UI 与窗口逻辑
- 产测与自检

### 3.2 基础设施模块

基础设施模块位于 `trunk/root_source/base` / `trunk/include` 等目录，负责：

- 模块注册
- 统一日志
- 事件分发
- 任务/消息传递
- 状态同步
- 存储和持久化能力

### 3.3 硬件驱动层

`drivers/` 提供外设抽象能力，涵盖：

- ADC
- UART/I2C
- 气压/压力/IMU
- LED / LCD / motor / battery
- flash / storage / key / sensors

## 4. 模块协作方式

推荐采用下列协作模型：

1. 事件/状态通过统一管理器或广播产生
2. 各模块按照职责关心自己的输入和输出
3. 跨域协调通过组合管理器或框架入口完成
4. 不在业务代码中直接绕过框架调用底层驱动

这是一种减轻耦合、提升可维护性的组织方式。

## 5. 设计约束

- `trunk/` 不能依赖 `overlay/` 里的实现细节
- `overlay/` 可以依赖 `trunk/` 提供的公共能力
- 修改跨模块接口时，必须同步更新相关文档
- 对外部边界（协议、状态机、资源分区）的修改应尽量保持向后兼容

## 6. 维护建议

在新增模块或调整业务状态时，建议同时检查：

- 相关 `boards/` 配置
- `overlay/` 钩子或服务实现
- 对应 `trunk/` 管理器和状态机
- `docs/architecture/` 中相关说明

避免仅在单一文件中建立隐式依赖。
