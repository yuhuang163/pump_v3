# 开发规范与模块接入指南

## 1. 代码分层约定

### 允许的依赖方向

```text
overlay/ -> trunk/ -> drivers/ -> platform_chip/
```

约束：

- `overlay` 可引用 `trunk` 的公共接口
- `trunk` 不应引用 `overlay` 细节实现
- `drivers` 提供底层能力，可被 `trunk` 使用
- 业务代码不应直接越过框架层访问底层寄存器或设备细节

## 2. 新模块接入 checklist

新增模块时，建议检查以下事项：

1. 确认模块职责是否清晰，属于框架能力还是产品能力
2. 选择正确目录：`trunk/root_source/` 或 `overlay/`
3. 若需要产品特定行为，优先使用 `overlay/framework_hooks/` 或对应产品目录
4. 补充必要宏开关和模块启用配置
5. 评估是否需要广播事件/订阅关系
6. 创建或更新相关文档与接口说明

## 3. 状态流设计

跨模块状态变化尽量遵循以下顺序：

- 事件源触发
- 上层管理器/状态机接收事件
- 逻辑处理并更新内部状态
- 发布相应通知/广播
- 需要时调用统一协调入口处理协调动作

不要让多个关注点分别分散处理同一状态切换。

## 4. 调试与维护

- 新功能优先保持在本层逻辑内，不要散落到全局文件
- 修改协议字段或状态枚举时，同步更新文档和调用方
- 复杂逻辑优先用状态机或策略表来表达，而不是层层分支嵌套
- 构建前先确认 `README.md` 中的命令与当前工程配置一致

## 5. 最佳实践

- 小步提交，确保每次改动都对应一个明晰的概念
- 先看调用链，再看实现细节
- 对外接口应尽量稳定，内部实现可有调整
- bug 修复时，必要时补充说明并同步文档

## 6. 文档同步要求

以下场景必须同步更新说明：

- 新广播事件
- 新状态机转移
- 协议变更
- 重要配置项新增/删除
- UI/LED/OTA 等跨模块流程调整

文档目录的维护入口为 [`docs/README.md`](../README.md)。
