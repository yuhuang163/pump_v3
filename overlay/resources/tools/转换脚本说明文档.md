# 图片格式转换工具使用说明

本目录包含用于图片格式转换的工具集，主要用于将 JPG/PNG 图片转换为嵌入式系统所需的格式。

## 🚀 快速开始

**最简单的转换方式（推荐新手）：**

```bash
# 将 PNG 图片转换为 BAJ 格式（固定最佳参数）
./png2baj_fixed.sh my_images/

# 就这么简单！转换后的 BAJ 文件在 out_my_images/ 目录
```

**固定参数配置**：`a4` + `YUV422` + `q99` + `不缩放` + `最大兼容性`

需要更多控制？查看 [方式3](#方式3-png-转-baj-自动对齐-推荐) 了解完全可配置版本。

## 使用方式

### 方式1: JPG 格式转换

将 JPG 图片转换为指定的 YUV 格式。

#### 语法

```bash
./jpg2jpg.sh <待转换目录> <YUV格式>
```

#### 参数说明

- **待转换目录**: 包含 JPG 图片的目录路径
- **YUV格式**: 目标格式，可选值：`YUV444` / `YUV422` / `YUV420`

#### 使用示例

```bash
/// 将 ./jpeg/ 目录下的所有 JPG 图片转换为 YUV420 格式
./jpg2jpg.sh ./jpeg/ YUV420

/// 转换为 YUV444 格式（更高质量）
./jpg2jpg.sh ./images/ YUV444
```

---

### 方式2: PNG 转 BAJ 格式

将 PNG 图片转换为 BAJ 格式（基础版本，需手动处理尺寸对齐）。

#### 语法

```bash
./png2baj.sh <alpha模式> <RLE压缩> <压缩质量> <YUV模式> <待转换目录>
```

#### 参数说明

1. **alpha模式**: `a4` 或 `a8`
   - `a4`: 4位 Alpha 通道（16级透明度）
   - `a8`: 8位 Alpha 通道（256级透明度，更平滑）

2. **RLE压缩**: `0` 或 `1`
   - `0`: 不使用 RLE 压缩
   - `1`: 启用 RLE 压缩（减小文件大小）

3. **压缩质量**: `0` 到 `99`
   - `99`: 损失最小的压缩（推荐）
   - `0`: 最大压缩率，质量最低

4. **YUV模式**: `420` / `422` / `444`
   - `420`: 最小文件，适合普通图片
   - `422`: 平衡模式
   - `444`: 最高质量，无色度子采样

5. **待转换目录**: PNG 图片所在目录

#### 使用示例

```bash
/// 高质量转换（a8 + RLE + 质量99 + YUV444）
./png2baj.sh a8 1 99 444 problem_png/

/// 平衡模式
./png2baj.sh a8 1 95 422 images/

/// 最小文件模式
./png2baj.sh a4 1 80 420 icons/
```

### 方式3: PNG 转 BAJ (自动对齐) ⭐推荐

**推荐使用此方式**，自动处理 16 像素对齐问题，避免图片尺寸异常。

#### 语法

```bash
./png2baj_resize.sh <alpha模式> <RLE压缩> <压缩质量> <YUV模式> <待转换目录> [最大尺寸]
```

#### 参数说明

前5个参数与方式2相同，新增第6个参数：

6. **最大尺寸**（可选）: 默认 `352`
   - 必须是 16 的倍数（如: 336, 320, 352, 512）
   - 图片超过此尺寸会自动等比缩放
   - 根据 YUV 模式自动应用解码宽度限制

#### 使用示例

```bash
/// 使用默认最大尺寸 352
./png2baj_resize.sh a8 1 99 444 problem_png/

/// 指定最大尺寸为 336
./png2baj_resize.sh a8 1 99 444 problem_png/ 336

/// 使用 YUV422 模式（支持更大的 512 宽度）
./png2baj_resize.sh a8 1 99 422 large_images/ 512

/// 小图标转换（最大 320）
./png2baj_resize.sh a8 1 99 420 icons/ 320
```

#### ✨ 新脚本特性

- ✅ **自动拷贝原始PNG文件**：不修改原图，保留备份
- ✅ **自动检测图片尺寸**：智能判断是否需要调整
- ✅ **可配置最大尺寸**：默认352，可指定336/320等16的倍数
- ✅ **自动缩放超大图片**：等比缩放并满足16像素对齐要求
- ✅ **自动对齐到16倍数**：确保符合 VGLite GPU 要求
- ✅ **自动清理临时文件**：转换完成后清理中间文件
- ✅ **避免尺寸异常**：解决360x360图片变成368x368的问题

### 方式4: PNG 转 BAJ (固定参数) 🚀最简单

**推荐日常使用**，固定最佳参数配置，只需指定输入目录即可。

#### 语法

```bash
./png2baj_fixed.sh <待转换目录> [输出目录]
```

#### 参数说明

1. **待转换目录**（必需）: 包含 PNG 图片的目录路径
2. **输出目录**（可选）: 输出 BAJ 文件的目录，默认为 `out_<输入目录名>`

#### 固定参数配置

| 参数 | 值 | 说明 |
|-----|-----|------|
| Alpha模式 | `a4` | 4位Alpha通道，节省空间 |
| 压缩模式 | `RLE (1)` | 启用RLE压缩 |
| JPEG质量 | `99` | 最高质量 |
| YUV采样 | `422` | 最佳兼容性，最大解码宽度512 |
| 图片缩放 | **不缩放** | 保持原始尺寸 |

#### 使用示例

```bash
/// 最简单用法（输出到默认目录）
./png2baj_fixed.sh my_images/

/// 指定输出目录
./png2baj_fixed.sh my_images/ output/

/// 转换当前目录下的PNG
./png2baj_fixed.sh ./ ../output/
```

#### ✨ 固定参数脚本特性

- 🚀 **参数最少**：只需1-2个参数，使用最简单
- ✅ **最佳配置**：预设 a4+YUV422+q99，适合大多数场景
- ✅ **不缩放图片**：保持原始尺寸，不改变图片大小
- ✅ **自动拷贝原图**：不修改原始PNG文件
- ✅ **最佳兼容性**：YUV422支持最大512宽度
- ✅ **空间优化**：a4模式节省约80% Alpha数据
- ✅ **批量转换**：适合批量处理图片资源
- ✅ **文件名信息完整**：包含尺寸、Alpha模式、质量、YUV模式

#### 💡 何时使用固定参数版本？

| 场景 | 推荐脚本 | 原因 |
|-----|---------|------|
| 日常批量转换 | `png2baj_fixed.sh` ⭐⭐⭐ | 参数少，操作快 |
| 需要缩放图片 | `png2baj_resize.sh` | 支持自动缩放 |
| 需要定制参数 | `png2baj_resize.sh` | 全参数可配置 |
| 需要a8透明度 | `png2baj_resize.sh` | 固定版只支持a4 |
| 需要YUV444/420 | `png2baj_resize.sh` | 固定版只支持YUV422 |

### 方式5: BAJ 转 TXT 数据文件

将 BAJ 格式文件转换为十六进制 TXT 数据文件，用于嵌入式系统直接使用（C数组格式）。

#### 语法

```bash
./baj_to_txt.sh <输入路径> [选项]
```

#### 参数说明

1. **输入路径**（必需）: BAJ 文件路径或包含 BAJ 文件的目录

#### 选项说明

- `-o <目录>`: 指定输出目录（默认：BAJ文件所在目录）
- `-n <文件名>`: 指定输出文件名（仅单文件模式有效）
- `-r`: 递归处理子目录（仅目录模式有效）
- `-h, --help`: 显示帮助信息

#### 使用示例

```bash
### 转换单个文件（输出到同目录）
./baj_to_txt.sh input.baj

### 转换单个文件并指定输出目录
./baj_to_txt.sh input.baj -o output_dir

### 转换单个文件并指定输出文件名
./baj_to_txt.sh input.baj -o output_dir -n output.txt

### 批量转换目录下所有BAJ文件
./baj_to_txt.sh out_img_a4_yuv420/

### 批量转换并指定输出目录
./baj_to_txt.sh out_img_a4_yuv420/ -o txt_output/

### 递归转换子目录中的BAJ文件
./baj_to_txt.sh out_img_a4_yuv420/ -o txt_output/ -r
```

#### ✨ BAJ转TXT特性

- ✅ **十六进制格式**：每行16字节，格式化为0x00, 0x01, ...
- ✅ **C数组格式**：可直接复制到C代码中使用
- ✅ **支持单文件和批量转换**：灵活处理不同场景
- ✅ **递归目录支持**：自动处理子目录结构
- ✅ **保持目录结构**：递归模式下保持原有目录层级
- ✅ **自动统计字节数**：显示转换的总字节数

### 方式7: BIN 后缀批量改名为 PNG（仅改名）

将 `overlay/resources/img/` 目录下（或你指定目录下）的 `*.bin` 文件**批量改名为 `*.png`**。

⚠️ 注意：此脚本**只修改文件名后缀**，不做图片内容格式转换。请确保这些 `.bin` 文件实际存放的是 PNG 格式数据（只是后缀写错）。

#### 语法

```bash
./bin2png_rename.sh [TARGET_DIR] [--dry-run] [--force]
```

#### 参数说明

- **TARGET_DIR**（可选）: 要处理的目录。默认：`overlay/resources/img/`
- **--dry-run**（可选）: 只预览将要执行的 `mv` 操作，不实际改名
- **--force**（可选）: 若目标 `.png` 已存在则覆盖；默认存在则跳过并提示

#### 使用示例

```bash
### 默认：处理 overlay/resources/img/（推荐）
./bin2png_rename.sh

### 预览将要改名哪些文件（不实际执行）
./bin2png_rename.sh --dry-run

### 指定目录
./bin2png_rename.sh ./some_img_dir/

### 若同名 .png 已存在则覆盖（谨慎）
./bin2png_rename.sh --force
```

## 参数详解

### Alpha 模式选择

| 模式 | 透明度级别 | 文件大小 | 适用场景 |
|------|-----------|---------|----------|
| `a4` | 16级 | 较小 | 简单图标、不需要平滑透明度 |
| `a8` | 256级 | 较大 | 需要平滑透明渐变的图片 |

### YUV 模式对比

| 模式 | 色度采样 | 质量 | 文件大小 | 最大解码宽度 |
|------|---------|------|---------|-------------|
| YUV420 | 4:2:0 | 一般 | 最小 | **336** |
| YUV422 | 4:2:2 | 较好 | 中等 | **512** |
| YUV444 | 4:4:4 | 最佳 | 最大 | **336** |

### 压缩质量建议

- **99**: 高质量图片、重要UI界面（推荐）
- **95**: 一般图片、平衡质量和大小
- **85-90**: 背景图片
- **70-80**: 临时图片、不重要的装饰图
- **< 70**: 不推荐，质量损失明显

## 注意事项

### ⚠️⚠️⚠️⚠️ 重要约束（必读）

```
【硬件限制】
YUV420/YUV444 的最大解码宽度为 336
YUV422 的最大解码宽度为 512
VGLite GPU 要求图片宽度必须16像素对齐

【自动处理方案】
使用 png2baj_resize.sh 或 png2baj_fixed.sh 自动处理对齐问题
```

### ⚠️⚠️⚠️⚠️⚠️ 尺寸限制详解

| YUV模式 | 最大解码宽度 | 推荐最大尺寸 | 说明 |
|---------|-------------|-------------|------|
| YUV420 | **336** | 336x336 | 超过此宽度会解码失败 |
| YUV444 | **336** | 336x336 | 超过此宽度会解码失败 |
| YUV422 | **512** | 512x512 | 支持更大图片 ⭐ |

### ⚠️⚠️⚠️⚠️⚠️ VGLite GPU 对齐要求

- 图片宽度**必须**是 **16 的倍数**（如：320、336、352、368、512）
- 不符合要求会导致显示异常或解码失败
- 360x360 的图片会被自动对齐为 368x368（可能超出屏幕）
- **推荐方案**：使用 `png2baj_resize.sh` 预先缩放到 352x352
- **简单方案**：使用 `png2baj_fixed.sh` 保持原始尺寸（不缩放）

### ⚠️ 文件路径

- 避免使用包含空格的目录名
- 使用相对路径或绝对路径
- 确保目录存在且有读写权限

### ⚠️ 图片格式

- JPG 图片不支持透明度
- PNG 图片支持透明度（通过 alpha 通道）
- 确保原始图片质量良好

### 转换方式选择指南

#### 场景A：需要硬件JPEG解码加速（推荐）
```
PNG图片 → [png2baj_fixed.sh] → BAJ格式 → [baj_to_txt.sh] → TXT数据 → 嵌入式系统
             压缩+YUV转换           十六进制格式        C数组格式      硬件加速
```

**优点**：
- ✅ 文件大小最小（压缩率高）
- ✅ 硬件JPEG解码器加速
- ✅ 节省存储空间
- ✅ 解码速度快

**适用**：需要显示大量图片、存储空间有限、需要快速解码

#### 场景B：直接使用PNG数据（简单）
```
PNG图片 → [png_to_txt.sh] → TXT数据 → 嵌入式系统
            保持原格式       C数组格式     软件解码
```

**优点**：
- ✅ 转换步骤最少
- ✅ 保留PNG完整格式
- ✅ 适合小图标

**缺点**：
- ❌ 文件较大（未压缩）
- ❌ 需要软件PNG解码器
- ❌ 解码速度较慢

**适用**：小图标、不需要频繁更新、解码性能要求不高

## 常见问题

### Q1: 为什么转换后图片尺寸变大了？

**A:** 原图尺寸不是16的倍数，被自动对齐。例如：360x360 → 368x368

**解决方案：** 使用 `png2baj_resize.sh` 并设置合适的最大尺寸
```bash
/// 将360x360自动缩放到352x352（16的倍数）
./png2baj_resize.sh a8 1 99 444 images/ 352
```

### Q2: 转换失败，提示 "command not found: convert"

**A:** 未安装 ImageMagick

**解决方案：**
```bash
/// RHEL/CentOS
sudo yum install ImageMagick

/// Ubuntu/Debian  
sudo apt install imagemagick
```

### Q3: 图片显示有锯齿或色块

**A:** 可能原因：
1. YUV420 色度采样不足
2. 压缩质量过低
3. 使用了 a4 而非 a8

**解决方案：**
```bash
/// 使用更高的质量参数
./png2baj_resize.sh a8 1 99 444 images/ 336
```

### Q4: 如何批量转换多个目录？

**A:** 使用循环脚本
```bash
/// 创建批量转换脚本
for dir in dir1 dir2 dir3; do
    ./png2baj_resize.sh a8 1 99 444 "$dir/" 336
done
```

### Q5: 原图会被修改吗？

**A:** 
- `png2baj.sh`: 会直接修改原图
- `png2baj_resize.sh`: **不会修改原图**，会自动创建备份（`*_original.png`）

### Q6: YUV444 和 YUV420 哪个更好？

**A:** 取决于需求：

| 考虑因素 | 推荐模式 |
|---------|---------|
| 存储空间有限 | YUV420 |
| 需要最佳质量 | YUV444 |
| 图片较大（>336px） | YUV422 |
| 平衡质量和大小 | YUV422 |

### Q7: 转换后文件很大怎么办？

**A:** 可以尝试：
1. 降低压缩质量（99 → 90）
2. 使用 YUV420 而非 YUV444
3. 使用 a4 而非 a8（如果不需要平滑透明度）
4. 确保启用了 RLE 压缩（参数设为 1）

### Q8: 应该使用哪个脚本？

**A:** 快速选择指南：

```
需要批量转换，不想调参数？
  ↓ YES
  使用 png2baj_fixed.sh ⭐⭐⭐⭐⭐ 最简单！

图片需要缩小（超过352x352）？
  ↓ YES
  使用 png2baj_resize.sh 并设置最大尺寸

需要a8透明度（256级）？
  ↓ YES
  使用 png2baj_resize.sh a8 1 99 422 dir/

需要YUV444最高色彩质量？
  ↓ YES
  使用 png2baj_resize.sh a8 1 99 444 dir/ 336

以上都不需要？
  ↓ YES
  使用 png2baj_fixed.sh ⭐ 日常推荐！
```

**对比表：**

| 需求 | 推荐脚本 | 命令示例 |
|-----|---------|---------|
| 快速批量转换 | `png2baj_fixed.sh` | `./png2baj_fixed.sh images/` |
| 需要缩放图片 | `png2baj_resize.sh` | `./png2baj_resize.sh a4 1 99 422 images/ 352` |
| 需要a8透明度 | `png2baj_resize.sh` | `./png2baj_resize.sh a8 1 99 422 images/` |
| 需要YUV444 | `png2baj_resize.sh` | `./png2baj_resize.sh a8 1 99 444 images/ 336` |
| 保持原始尺寸 | `png2baj_fixed.sh` | `./png2baj_fixed.sh images/` |

### Q9: 如何在C代码中使用转换后的TXT数据？

**A:** 使用方法如下：

```c
/// 1. 包含TXT文件内容到C代码中
const unsigned char image_data[] = {
    0x42,0x41,0x4a,0x00,0x60,0x01,0x60,0x01,  /// 从TXT文件复制
    0x61,0x04,0x00,0x00,0x63,0x0d,0x00,0x00,
    /// ... 更多数据
};

/// 2. 定义数组大小
const unsigned int image_data_size = sizeof(image_data);

/// 3. 使用数据
void load_image(void) {
    /// BAJ格式：使用硬件JPEG解码器
    decode_baj_image(image_data, image_data_size);
    
    /// 或PNG格式：使用PNG解码库
    decode_png_image(image_data, image_data_size);
}
```

### Q10: BAJ转TXT和PNG转TXT有什么区别？

**A:** 主要区别：

| 对比项 | BAJ转TXT | PNG转TXT |
|-------|---------|---------|
| **源格式** | BAJ压缩格式 | PNG原始格式 |
| **文件大小** | 小（已压缩） | 较大（PNG压缩） |
| **解码方式** | 硬件JPEG解码器 | 软件PNG解码库 |
| **解码速度** | 快（硬件加速） | 慢（软件解码） |
| **适用场景** | 大量图片、需要快速显示 | 小图标、简单场景 |
| **转换步骤** | 需要先PNG→BAJ | 直接转换 |

**推荐：** 大多数情况使用 **BAJ转TXT**（更高效）

### Q11: 如何批量转换并保持目录结构？

**A:** 使用 `-r` 递归选项：

```bash
### 源目录结构：
### images/
### ├── icons/
### │   ├── home.png
### │   └── settings.png
### └── backgrounds/
###     ├── bg1.png
###     └── bg2.png

### 批量转换PNG到BAJ（保持结构）
./png2baj_fixed.sh images/

### 批量转换BAJ到TXT（保持结构）
./baj_to_txt.sh out_images/ -o txt_data/ -r

### 结果：
### txt_data/
### ├── icons/
### │   ├── home_360x360_a4_q99_422.txt
### │   └── settings_360x360_a4_q99_422.txt
### └── backgrounds/
###     ├── bg1_360x360_a4_q99_422.txt
###     └── bg2_360x360_a4_q99_422.txt
```

### Q12: TXT文件太大怎么办？

**A:** TXT文件是给人看的格式，实际使用时建议：

1. **直接使用二进制文件**（不转TXT）：
   ```c
   /// 在编译时通过链接器包含二进制文件
   extern const unsigned char _binary_image_baj_start[];
   extern const unsigned char _binary_image_baj_end[];
   ```

2. **如果必须使用TXT**：
   - 优先使用BAJ格式（比PNG小很多）
   - 使用压缩工具压缩TXT文件
   - 转换后直接编译到固件中

3. **最佳方案**：
   ```bash
   ### 将BAJ文件直接包含到固件中，不转TXT
   ### 在Makefile中添加：
   ### OBJCOPY = arm-none-eabi-objcopy
   ### $(OBJCOPY) -I binary -O elf32-littlearm image.baj image.o
   ```
